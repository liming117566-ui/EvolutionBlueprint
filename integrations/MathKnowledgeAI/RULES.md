## 1. 总原则

1. **知识点库稳定优先**  
   `01_Knowledge/` 是基础知识库，默认不因普通错题、问答而修改。
2. **错题必须可追溯**  
   每一道错题都必须关联至少 1 个知识点页面，使用 Obsidian 双链。
3. **字段统一优先**  
   错题统计统一使用英文 frontmatter key；页面展示可以使用中文列名。
4. **所有输出服务于复习**  
   错题页不仅记录答案，还要记录错因、方法、变式题、掌握度和下一次复习日期。
5. **不确定时先确认**  
   如果题目文字、图片识别、知识点归属或用户原错误不明确，应先询问用户，不要强行归档。

## 2. 自动化、统计与稳定性原则

1. **Dashboard query-driven**  
   `Home.md`、`ReviewQueue.md`、`WeakPoints.md`、`LearningProgress.md`、`DataHealth.md` 尽量通过 Dataview 自动统计，不手工维护统计表。
2. **AI 负责生成与更新数据**  
   AI 主要负责生成错题页、更新复习状态、生成变式题和复盘建议。
3. **字段完整性优先**  
   每次新增错题必须填写：`knowledge`、`area`、`error_type`、`status`、`mastery`、`next_review`、`review_stage`。
4. **长期稳定优先**  
   统计字段使用英文 key；中文只用于显示别名。新增字段必须同步更新模板、Dashboard 和测试规则。

## 4. 知识点库规则

### 4.1 默认保护

默认不修改 `01_Knowledge/` 下的知识点页面。

允许修改的情况：

1. 用户明确说“优化知识点”“补充知识点”“修正知识点”。
2. 用户要求批量建立或重构知识点库。
3. 发现明显格式错误、断链、目录顺序问题或统计字段不一致，且修改风险很低。

### 4.2 知识点链接规范

错题关联知识点时，优先使用精确路径链接，避免同名知识点歧义。

```markdown
[[人教版初中数学AI学习库/01_Knowledge/05_九年级上册/22_第二十二章 二次函数/03. 二次函数一般式与顶点式|二次函数一般式与顶点式]]
```

如果知识点名称全库唯一，可以使用短链接：

```markdown
[[二次函数一般式与顶点式]]
```

## 5. 错因分类规则

`error_type` 只使用以下 5 类之一：

1. `概念不清`：定义、性质、判定、公式理解错误。
2. `方法不会`：知道概念，但不会选择解法或建模方法。
3. `计算错误`：符号、运算、化简、代入等计算失误。
4. `审题失误`：漏看条件、看错问法、单位或范围理解错误。
5. `书写不规范`：步骤缺失、依据不明、证明表达不完整。

如果一道题有多个错因：

- `error_type` 写最主要错因。
- `secondary_error_type` 写次要错因，可为空。
- 具体说明写入正文“错因分析”。

## 6. 错题字段规范

错题页 frontmatter 必须使用以下字段：

```yaml
---
title: 错题标题
date: YYYY-MM-DD
tags:
  - 错题
  - 人教版
  - 初中数学
grade: 七年级上册
chapter: 第一章 有理数
area: 数与代数
knowledge:
  - "[[知识点页面]]"
error_type: 概念不清
secondary_error_type: 
difficulty: 中
mastery: 未掌握
status: 待复习
review_stage: 1
last_review: 
attempt_count: 0
next_review: YYYY-MM-DD
review_dates:
  - YYYY-MM-DD
  - YYYY-MM-DD
  - YYYY-MM-DD
  - YYYY-MM-DD
review_result: 
source_image: 人教版初中数学AI学习库/00_Inbox/错题照片/原图文件名.png
ocr_text: 
annotated_image: 
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

字段取值规则：

| 字段 | 允许值或说明 |
|---|---|
| `error_type` | 概念不清 / 方法不会 / 计算错误 / 审题失误 / 书写不规范 |
| `secondary_error_type` | 可为空；如填写，使用同一套错因分类 |
| `area` | 数与代数 / 图形与几何 / 统计与概率 / 综合与实践 |
| `difficulty` | 易 / 中 / 难 |
| `mastery` | 未掌握 / 基本掌握 / 已掌握 |
| `status` | 待复习 / 复习中 / 已掌握 / 需重做 |
| `review_stage` | 当前复习轮次，1/2/3/4 对应 1/3/7/14 天 |
| `last_review` | 上一次复习日期，可为空 |
| `attempt_count` | 重做次数，默认 0 |
| `next_review` | 下一次复习日期，用于 Dashboard 查询 |
| `review_result` | 通过 / 犹豫 / 错误，可为空 |
| `source_image` | 原始图片或草稿路径；没有则留空 |
| `ocr_text` | OCR 文本文件路径；没有则留空 |
| `annotated_image` | 批注后图片路径；没有则留空 |

### 字段更新规则

**`last_review`**：
- 每次完成复习后更新为当天日期（YYYY-MM-DD）。
- 初次创建错题时可为空。

**`attempt_count`**：
- 每次复习（无论结果如何）后 +1。
- 状态变为 `需重做` 后重新从第 1 天开始时，计数器不重置（累计统计总复习次数）。
- 初次创建错题时设为 0。

**`review_stage`**：
- 初次创建错题时设为 1。
- 每次复习 `通过` 后 +1（最多到 4）。
- 复习 `错误` 后重置为 1。
- 复习 `犹豫` 后保持不变，但追加 1 次次日复习。

## 7. 错题录入流程

处理 `00_Inbox/` 中的图片、截图或草稿时，按以下流程：

1. **识别题目**：用 OCR 或人工阅读提取题目文字、图形条件和用户原答案。
2. **确认信息**：如果题干、图形或用户错误答案不清楚，先询问用户。
3. **定位知识点**：从 `01_Knowledge/` 中查找对应知识点，不随意新建知识点。
4. **分析错因**：选择 `error_type` 和必要的 `secondary_error_type`。
5. **生成错题页**：写入 `02_ErrorBank/`，使用统一字段模板。
6. **生成变式题**：自动生成 2–3 道同类型变式题，可写在错题页，也可拆到 `03_Practice/`。
7. **设置复习日期**：默认按 1/3/7/14 天生成 `review_dates`，将最近一次写入 `next_review`，并设置 `review_stage: 1`。
8. **处理原始材料**：原图不删除；可移动到 `00_Inbox/已处理/`，并在 `source_image` 中保留路径。
9. **验证 Dashboard**：确认新增错题能被 ReviewQueue、WeakPoints、LearningProgress 等 Dashboard 正确捕获（Dashboard 通过 Dataview 自动统计，无需手工更新）。

错题文件建议命名：

```text
YYYY-MM-DD_知识点名_简短题型.md
```

## 9. 提问答疑流程

当用户直接问数学问题时：

1. 先判断对应知识点，并读取相关错题记录。
2. 如果用户之前在该知识点有错题，先提醒：
   > 你之前在这个知识点错过 N 道题，主要错因是……
3. 用通俗语言讲解，优先讲“为什么”，再讲“怎么算”。
4. 给出规范解题步骤。
5. 如果暴露出新的薄弱点，生成 1 道巩固题。
6. 普通问答不写入 `01_Knowledge/`；如需保存，写入 `03_Practice/` 或 `04_Dashboard/学习问答记录.md`。

## 10. 复习队列规则

默认间隔复习节奏：

- 第 1 天
- 第 3 天
- 第 7 天
- 第 14 天

复习结果规则：

| 复习结果 | 后续处理 |
|---|---|
| `通过` | 进入下一次复习；最后一次通过后设为 `已掌握` |
| `犹豫` | 保持 `复习中`，可追加 1 次次日复习 |
| `错误` | 状态设为 `需重做`，重新从第 1 天复习开始 |

推荐维护文件：

- `04_Dashboard/Home.md`：学习仪表盘入口。
- `04_Dashboard/ReviewQueue.md`：每日待复习错题。
- `04_Dashboard/ReviewPlan.md`：本周复习计划。
- `04_Dashboard/WeakPoints.md`：薄弱知识点统计。
- `04_Dashboard/LearningProgress.md`：章节和模块掌握度统计。
- `04_Dashboard/DataHealth.md`：字段完整性和异常数据检查。

## 11. 每周复盘流程

每周日执行一次：

1. 统计本周新增错题数量。
2. 按知识点汇总错题，生成薄弱点 Top 3。
3. 按错因分类统计：概念不清、方法不会、计算错误、审题失误、书写不规范。
4. 检查孤儿错题：没有关联知识点的错题必须补链。
5. 给每个薄弱点生成复习建议，例如：
   - 复习 1 个知识点页
   - 重做 2 道错题
   - 新做 3 道同类变式题
6. 更新 `04_Dashboard/WeakPoints.md`、`04_Dashboard/ReviewPlan.md` 和 `04_Dashboard/LearningProgress.md`。

## 13. 图片与附件管理规则

### 13.1 目录规范

所有错题图片和附件统一进入 `05_Assets/` 管理：

| 目录 | 用途 |
|---|---|
| `05_Assets/01_RawImages/` | 原始图片；Obsidian 新粘贴附件默认进入这里 |
| `05_Assets/02_ProcessedImages/` | 已处理并已关联错题页的图片 |
| `05_Assets/03_OCR/` | OCR 识别后的文字结果 |
| `05_Assets/04_Annotated/` | 批注、裁剪或标记后的图片 |
| `05_Assets/99_Archive/` | 不再参与当前学习流的归档附件 |

### 13.2 图片处理流程

1. 用户拍照或截图后，优先放入 `00_Inbox/错题照片/`。
2. Obsidian 中直接粘贴的图片默认进入 `05_Assets/01_RawImages/`。
3. AI 处理错题后，原图不删除，移动或复制到 `05_Assets/02_ProcessedImages/`。
4. OCR 结果保存到 `05_Assets/03_OCR/`，并在错题页 `ocr_text` 字段记录路径。
5. 若生成批注图，保存到 `05_Assets/04_Annotated/`，并在错题页 `annotated_image` 字段记录路径。
6. 错题页必须用 `source_image` 记录原始图片或处理后图片路径。

### 13.3 图片命名规范

图片文件命名使用：

```text
YYYY-MM-DD_年级_章节_知识点_序号.扩展名
```

示例：

```text
2026-04-30_七上_有理数_有理数加减_001.jpg
```

命名原则：

1. 文件名尽量短，不使用空格。
2. 知识点名称过长时可简写。
3. 同一知识点同一天多张图片用 `001`、`002` 递增。
4. 原始文件名不清晰时，处理后必须重命名。

### 13.4 图片链接规范

错题页正文中推荐嵌入图片：

```markdown
## 原图

![[2026-04-30_七上_有理数_有理数加减_001.jpg]]
```

frontmatter 中保留可统计路径：

```yaml
source_image: 人教版初中数学AI学习库/05_Assets/02_ProcessedImages/2026-04-30_七上_有理数_有理数加减_001.jpg
ocr_text: 人教版初中数学AI学习库/05_Assets/03_OCR/2026-04-30_七上_有理数_有理数加减_001.md
annotated_image: 人教版初中数学AI学习库/05_Assets/04_Annotated/2026-04-30_七上_有理数_有理数加减_001.png
```

## 14. Dashboard 查询约定

所有 Dashboard 和知识点页 Dataview 统一使用以下字段：

- `knowledge`：关联知识点列表。
- `area`：知识模块。
- `error_type`：主要错因。
- `secondary_error_type`：次要错因。
- `next_review`：下一次复习日期。
- `review_dates`：全部计划复习日期。
- `review_stage`：当前复习轮次。
- `last_review`：上一次复习日期。
- `attempt_count`：重做次数。
- `status`：复习状态。
- `mastery`：掌握程度。

禁止再使用旧字段名 `错因`、`复习日期` 作为统计主字段。

## 15. 测试与验收规则

每次修改规则、错题模板、Dashboard 查询或知识点页 Dataview 后，必须执行以下验收。

### 15.1 知识点页抽样检查

随机抽取 3 个知识点页，检查其“关联错题自动汇总” Dataview 是否使用统一字段：

- `knowledge`
- `error_type`
- `secondary_error_type`
- `status`
- `next_review`

验收标准：

1. 不再使用旧字段 `错因`、`复习日期` 作为统计主字段。
2. 查询路径指向 `人教版初中数学AI学习库/02_ErrorBank`。
3. 查询条件能兼容：
   - frontmatter 中的 `knowledge` 字段；
   - 正文中的知识点双链。

### 15.2 模拟错题验证

新建 1 条模拟错题，用于验证完整数据链路。

模拟错题必须包含以下 frontmatter 字段：

```yaml
knowledge:
  - "[[某个知识点页面]]"
error_type: 计算错误
secondary_error_type: 
difficulty: 中
mastery: 未掌握
status: 待复习
review_stage: 1
last_review: 
attempt_count: 0
next_review: YYYY-MM-DD
review_dates:
  - YYYY-MM-DD
review_result: 
```

验收标准：

1. 对应知识点页能在“关联错题自动汇总”中显示该错题。
2. [[人教版初中数学AI学习库/04_Dashboard/Home]] 的“今日待复习”能查到该错题。
3. [[人教版初中数学AI学习库/04_Dashboard/ReviewQueue]] 能查到该错题。
4. [[人教版初中数学AI学习库/04_Dashboard/WeakPoints]] 能按知识点统计到该错题。
5. [[人教版初中数学AI学习库/04_Dashboard/LearningProgress]] 能按 `area`、年级、章节或掌握度统计到该错题。
6. [[人教版初中数学AI学习库/04_Dashboard/DataHealth]] 不显示该错题为字段缺失或异常。

### 15.3 数据健康检查

每次批量处理错题后，检查是否存在以下异常：

1. 没有 `knowledge` 的孤儿错题。
2. 没有 `error_type` 的错题。
3. 没有 `next_review` 且 `status != 已掌握` 的错题。
4. `status` 不在允许值中的错题。
5. `mastery` 不在允许值中的错题。
6. 没有 `area` 的错题。
7. 没有 `review_stage` 的错题。

### 15.4 测试数据处理

如果创建了模拟错题：

1. 文件名必须包含 `TEST` 或 `模拟测试`，例如：

```text
TEST_YYYY-MM-DD_知识点名_模拟错题.md
```

2. 测试完成后，应二选一：
   - 删除模拟错题；或
   - 移动到 `99_Backups/测试数据/`。

3. 不允许把模拟错题长期保留在正式 `02_ErrorBank/` 统计中。

## 16. 安全规则

1. 批量修改前，先备份到 `99_Backups/`。
2. 不删除用户原始资料，除非用户明确要求。
3. 不确定题意、图形或答案时，先提问确认。
4. 修改知识点库时，尽量保持原有标题、链接和 frontmatter 稳定。
5. 大批量生成内容后，必须检查 Markdown 代码块、frontmatter 和文件数量。
